## 1. 测试策略

| 层 | 工具 | 范围 | 外部依赖 |
|---|---|---|---|
| 后端单元/集成 | JUnit 5 + Spring Boot Test + MockMvc | 全部业务接口全链路（认证/物品/认领/论坛/公告/消息/管理/缓存/矩阵） | H2(MySQL 兼容模式) + InMemoryRedis 桩，CI 零中间件 |
| 后端覆盖率 | JaCoCo `coverage-gate` | 行覆盖 ≥0.60 门禁（S7 验收线） | `mvn verify -Pcoverage-gate` |
| 前端单元 | Vitest (node 环境) | Axios 信封拦截器 / store 水合 / 守卫纯函数 | 无浏览器依赖 |
| 前端构建 | Vite build | 全页面编译 + 路由完整性 | — |
| UI 端到端 | Playwright(chromium) 真点击 | 游客→登录→发布→详情→论坛→用户中心→管理台 30 项断言 + pageerror 监听 + 截图视觉复核 | 本机起后端 jar + dev server |
| 真链路冒烟 | HTTP 脚本（真 MySQL 8 + 真 Redis db1） | 认证链/缓存键族/TTL/回写作业/检索排序 | 本机 lost_found_db |

设计纪律：
- 测试与生产同源 DDL：`schema-h2.sql` 由 `schema.sql` 机械转换（M1 契约测试双向比对列集合）。
- API 测试类一律类级 `@Transactional` 回滚（M4 教训：跨类共享 H2 时全局闸门——每日发布上限、种子计数——会被泄漏数据顶爆）；刻意不开事务的类（乐观锁一级缓存前提）以 `@AfterEach` 物理清理兜底。
- 缓存测试前置守卫 `TestCacheGuardExtension`（ServiceLoader 自动探测）：DB 回滚不回滚内存 Redis，每个用例起跑前清空 lf: 键族/PV 计数/防刷锁。
- 定时任务在测试 profile 全部拨到 24h 禁自动触发，由用例显式调用 `syncNow()` 驱动（消除调度线程与断言赛跑的假阳性）。

## 3. 覆盖率（JaCoCo LINE，`mvn verify -Pcoverage-gate`）

**全工程行覆盖 0.86（≥0.60 验收线，门禁实测通过）**

低覆盖区（均为可解释的残余路径，非逻辑盲区）：

| 包 | 覆盖率 | 未覆盖内容与理由 |
|---|---|---|
| com/campus/lf/job | 36% | 两个调度壳的异常兜底分支（任务内逻辑由 syncNow/remindTimeout 显式驱动全测）|
| module/user/entity·service | 52%/55% | 管理口 DTO 组装的可选字段分支；RBAC 聚合查询在 M2 已测 |
| module/storage | 58%/77% | 落盘 IOException 分支（需磁盘故障注入，毕设口径不模拟）|

指令覆盖 0.54 / 分支覆盖 0.23 偏低主因：Lombok 生成的 builder/equals 与防御性 catch 分支计入分母——与博客毕设 M11 同现象，验收线只钉 LINE（S7 口径）。
