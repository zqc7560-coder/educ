# 校园失物招领系统 · 开发计划

> 软件工程毕业设计 · v1.0（2026-11）
> 本计划为评审草稿，供指导教师/同学批注修改

## 1. 项目背景与目标

高校校园内失物与拾物信息分散在 QQ 群、朋友圈、公告栏等渠道，存在信息孤岛、检索困难、
归还效率低、冒领难核实等问题。本项目旨在设计并实现一个**校园失物招领系统**，为全校
师生提供统一的失物登记、拾物发布、智能匹配、认领核验与流程管理能力。

**可度量目标**
- 失物/拾物信息发布 ≤ 30 秒完成（表单简化 + 图片上传）
- 关键词与分类检索响应 < 500ms（数据库索引 + Redis 缓存）
- 相似物品自动推荐：发布失物后主动推送候选拾物（规则匹配 + 相似度打分）
- 认领流程闭环：申请 → 核验 → 确认归还，全程留痕可审计
- 完成软件工程全套产出：需求规格、概要/详细设计、测试报告、部署文档、毕业论文

## 2. 技术选型（与团队已有技能栈一致）

| 层 | 技术 | 说明 |
|---|---|---|
| 后端 | Java 17 + Spring Boot 3 + MyBatis-Plus | RESTful API |
| 前端 | Vue 3 + Vite + Element Plus | 管理端 + 用户端同一工程分路由 |
| 数据库 | MySQL 8.0 | utf8mb4，全文检索用 ngram |
| 缓存 | Redis 7 | 热点列表、验证码、会话黑名单 |
| 认证 | Spring Security + JWT | 无状态登录，角色 RBAC |
| 文件 | 本地磁盘存储（预留 OSS 接口） | 图片落盘 + 类型白名单校验 |
| 部署 | Docker Compose（mysql/redis/app/nginx） | 一键起全栈 |
| 测试 | JUnit 5 + H2（接口测试）/ Vitest（前端） | CI 跑覆盖率门禁 |

## 3. 阶段划分与时间计划（16 周）

| 阶段 | 周次 | 内容 | 产出/验收 |
|---|---|---|---|
| S1 需求分析 | W1–W2 | 调研校园场景、竞品分析（校内群/牛政通等）、用例建模 | 需求规格说明书、用例图、原型图（低保真） |
| S2 系统设计 | W3–W4 | 架构设计、数据库设计（ER→DDL）、接口设计、认领状态机设计 | 概要/详细设计说明书、API 文档 |
| S3 基础框架 | W5 | 工程骨架、统一响应/异常/日志、CI 流水线、登录注册 | 可运行的骨架 + 单测 |
| S4 核心业务 | W6–W9 | 物品发布/检索/详情、图片上传、认领流程状态机、消息通知 | 用户端全流程可用 |
| S5 管理端 | W10–W11 | 审核队列、敏感词、统计看板、用户治理、置顶/加急 | 管理端全流程可用 |
| S6 增强特性 | W12 | 相似推荐、按校区/楼栋筛选、收藏与订阅、导出报表 | 答辩亮点功能冻结 |
| S7 测试收口 | W13–W14 | 功能回归、并发压测（JMeter）、覆盖率 ≥60% 门禁、安全自查（越权/XSS/上传） | 测试报告 |
| S8 部署与论文 | W15–W16 | Docker 部署演练、演示数据准备、论文撰写与查重 | 可部署成品 + 论文定稿 |

**里程碑**：M1 需求冻结(W2末) → M2 设计评审通过(W4末) → M3 核心流程跑通(W9末) →
M4 功能冻结(W12末) → M5 测试通过(W14末) → M6 交付(W16末)。

## 4. 任务分解（WBS 摘要）

- **后端**：物品模块、认领流程模块、用户/权限模块、消息通知模块、统计模块、文件服务
- **前端**：用户端（首页/发布/详情/我的/认领交互）、管理端（审核/治理/看板）
- **数据**：11~13 张表（用户、物品、认领单、图片、分类、校区楼栋、消息、敏感词、统计、系统参数、操作日志）
- **测试**：接口自动化（认领状态机矩阵为重点）、单元测试（服务层）、压测场景 3 组
- **文档**：需求/设计/测试/部署四件套 + 论文

## 5. 风险与对策

| 风险 | 概率 | 影响 | 对策 |
|---|---|---|---|
| 认领纠纷/冒领设计不足 | 中 | 高 | 核验凭证字段 + 状态机 + 管理仲裁兜底，设计阶段评审定稿 |
| 图片存储与合规 | 中 | 中 | 类型魔数校验、大小限制、仅校园可见的权限隔离 |
| 16 周工期偏紧 | 中 | 高 | P0（发布/检索/认领闭环）先行，增强特性可裁剪 |
| 相似度匹配效果差 | 低 | 低 | 规则打分（分类+时间窗+文本重合度）即可，不依赖大模型 |
| 学业冲突（实习/考研） | 高 | 中 | 每阶段留 20% 缓冲；CI 保证随时可交付可演示状态 |

## 6. 验收标准（毕业交付物）

1. 可在 Docker Compose 一键启动的完整系统（含种子演示数据）
2. 后端测试 ≥ 120 例全绿，行覆盖率 ≥ 60%，接口文档与实现一致
3. 需求规格、设计、测试、部署四份文档 + 论文查重合格
4. 现场演示主流程：注册→发布拾物→搜索→申请认领→核验→确认归还→统计看板
