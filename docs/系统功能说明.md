# 校园失物招领系统 · 系统功能说明

> 软件工程毕业设计 · v1.0（2026-11）· 评审草稿

## 1. 角色定义

| 角色 | 说明 | 主要能力 |
|---|---|---|
| 游客 | 未登录访问者 | 浏览/搜索已发布的失物拾物信息（联系方式打码） |
| 学生（注册用户） | 全校师生 | 发布、认领、收藏、消息、个人管理全部动作 |
| 失物中心管理员（MANAGER） | 学生会/后勤工作人员 | 物品审核、敏感词、仲裁、统计 |
| 系统管理员（ADMIN） | 平台运维 | 管理员之上另有用户治理、系统参数、回收站、日志审计 |

## 2. 功能清单（优先级：P0 必须 / P1 应有 / P2 加分）

### 2.1 用户模块
- P0 注册（学号唯一 + 邮箱）、登录/登出（JWT）、防枚举登录错误
- P0 个人中心：资料修改、改密（全端下线）
- P1 头像上传；P2 微信/统一身份认证预留接口

### 2.2 物品信息模块（核心）
- P0 发布拾物/失物：分类、描述、校区-楼栋-位置三级地点、发生时间、
  联系方式、图片上传（1–6 张）、FOUND 件"物主核验问题"设置
- P0 检索：关键词全文搜索、按类型/分类/校区/时间范围筛选、
  发布时间/热度排序、分页
- P0 详情页：图片轮播、浏览次数累计、相似推荐（同分类+时间窗+地点+文本重合度 Top5）
- P0 编辑/下架/重新上架（仅本人）；P1 置顶申请与加急标记
- P1 收藏与"我的发布/我的收藏"管理；P2 到期自动沉底（30 天未处理提醒）

### 2.3 认领流程模块（核心）
- P0 在线申请认领：填写核验答案 + 补充描述
- P0 发布者核验：查看答案 → 通过/拒绝（理由必填）
- P0 确认归还：乐观锁防重复归还，成功后物品自动下架"已归还"，
  其余在途申请批量关闭
- P0 申请流转全程留痕（claim_log 可审计）
- P1 72h 超时提醒；P1 任一方可申请管理员仲裁（裁决+留言）
- P2 归还互评（信用分雏形，供后续风控）

### 2.4 消息通知模块
- P0 站内消息：审核结果、新认领申请、核验结果、确认归还、推荐匹配
- P1 未读红点与消息中心分页；P2 邮件提醒

### 2.5 管理端模块
- P0 物品审核队列（先审后发可配置开关）、违规下架（理由必填）
- P0 数据看板：总量/找回率/分类分布/近 7 日趋势/活跃排行
- P1 敏感词库管理；P1 仲裁工作台；P1 用户治理（禁言/封禁，护栏不可自禁）
- P1 系统参数（轮播公告、每日发布上限、审核开关等）
- P2 回收站与彻底删除；操作日志审计检索

### 2.6 平台能力
- P0 统一响应体与业务错误码；全局异常处理
- P0 RBAC 权限点控制（接口注解 + 前端菜单按权限渲染）
- P0 Redis 缓存热点列表 + 写后失效；图片魔数校验防伪装上传
- P1 XSS 防护（纯文本存储+前端转义）、接口频率限制防刷
- P1 Docker Compose 一键部署（mysql/redis/app/nginx + 幂等种子数据）
- P1 CI 自动化测试（后端 H2 全链路 + 前端单测，覆盖率 ≥60% 门禁）

## 3. 关键用例

**UC-1 发布拾物**：学生 A 捡到校园卡 → 选分类"卡证"→ 上传照片 →
设置核验问题（"卡片姓名是什么？"）→ 提交 →（开关开启时）进审核队列 →
审核通过上架并推送同校区近 7 日挂失校园卡的失主。

**UC-2 认领闭环**：失主 B 搜索/被推送 → 查看详情 → 提交认领申请并回答核验问题 →
A 查看答案判断属实 → 点"同意认领"约定交接 → B 拿到卡后 A 点"确认归还" →
系统下架物品、关闭 B 之外其他申请、双方收到消息。

**UC-3 纠纷仲裁**：多个申请人答案接近、发布者无法判断 → 申请管理员仲裁 →
管理员查看 claim_log 全程留痕与双方材料 → 裁决归属 → 当事人收通知。

**UC-4 审核治理**：管理员在队列看到疑似违规广告帖 → 驳回并填理由 →
申请人收消息可修改重提；敏感词命中在提交时即被拦截。

## 4. 非功能需求

- 性能：检索 P95 < 500ms（万级数据量）；发布 P95 < 1s（不含外网）
- 并发：100 并发发布/认领无超卖、无重复归还（乐观锁+唯一约束）
- 可用性：Redis 故障降级直查数据库不报 500
- 兼容性：Chrome/Edge 最新版 + 移动端 H5 自适应
- 数据安全：密码 BCrypt、图片权限隔离、越权测试全矩阵覆盖

## 5. 与近似系统的差异化

相比 QQ 群/表白墙式人工转发：结构化检索、可核验的认领留痕、
管理员仲裁兜底、找回率数据看板，是本系统的四个核心价值点。
