# 校园失物招领系统 · 开发方案

> 软件工程毕业设计 · v1.0（2026-11）· 评审草稿

## 1. 总体架构

```
┌─────────────────────────────────────────────┐
│  浏览器（学生/管理员）  移动端浏览器（H5 自适应）  │
└──────────────┬──────────────────────────────┘
               │ HTTPS
┌──────────────▼──────────────┐
│  Nginx（静态资源 + 反向代理）   │  ← /api → 应用
└──────────────┬──────────────┘

│  controller → service → mapper │
│  统一响应/全局异常/JWT过滤器/RBAC │
└───┬──────────┬──────────┬─────┘
┌───▼───┐ ┌────▼────┐ ┌───▼────┐
│ MySQL │ │ Redis   │ │ 本地文件 │
│ 主数据 │ │ 缓存/计数 │ │ 图片存储 │
└───────┘ └─────────┘ └────────┘
```

单体分层架构（毕设规模最优选）：不引入微服务，避免运维复杂度；
模块边界用包结构表达（item / claim / user / notice / admin / stats），
预留将来拆分可能。

## 3. 核心设计方案

### 3.1 物品域模型
- **统一物品表 `lost_item`**：type 区分 LOST（寻物启事）/FOUND（招领启事）；
  状态机：`草稿(可选)→待审核→已发布→已下架(物归原主/过期/违规)`，
  逻辑删除 + 回收站。
- 关键字段：标题、分类（证件/电子设备/书籍/卡证/钥匙/衣物/其他）、描述、
  丢失/拾获地点（校区-楼栋-具体位置三级）、时间、联系人、图片(1..6张)、
  物主核验问题（仅 FOUND 件，认领时须回答）。
- 冗余计数列（view_count / claim_count）随行为结算，避免 count(*) 热点。

### 3.2 认领流程状态机（本系统灵魂，答辩重点讲）
```
物品已发布
  └─ 申请人提交认领单（核验答案+自述凭证描述）→ claim: 待核验
       ├─ 发布者查看核验答案 → 通过 → 约定交接 → 确认归还（claim: 已完成, item: 已下架-已归还）
       ├─ 发布者拒绝（理由必填）→ claim: 已拒绝（申请人可二次申请）
       └─ 超时 72h 未处理 → 提醒；任一方可申请管理员仲裁 → claim: 仲裁中 → 管理员裁决
```
- 并发护栏：同一物品多申请并存允许，但确认归还采用**乐观锁+状态前置校验**，
  先到先得防重复归还；归还确认后其余申请自动置"已关闭"。
- 全程留痕：claim_log 记录每一步操作人/时间/理由，可审计。

### 3.3 匹配与推荐（规则版，不依赖 AI 也可跑）
- 发布 LOST 时：同分类 + 时间窗（±7 天）+ 地点同楼栋 + 标题/描述关键词重合度
  打分（Jaccard），Top 5 推荐并给发布者发站内信"可能匹配"。
- Redis 缓存热点检索结果（列表页 5min TTL，发布/审核动作后主动失效）。

### 3.3.1 论坛设计（图文帖 + 点赞 + 两级回复）
- **帖子 `forum_post`**：标题 + 富文本降级为"纯文本 + 图片(0–9 张)"，
  板块（失物交流/校园生活/求助，字典表驱动）；状态机复用物品模块口径：
  `待审核(开关开启时)→已发布→已下架(违规/作者自删)`，浏览量/回复数/点赞数
  冗余列随行为结算（GREATEST 钳非负，与博客 M5 同款）。
- **回复 `forum_reply` 两级封顶**：parent 必须顶级且同帖（越级 2302 语义），
  回复回复靠 reply_to_uid 自动 @ 前一层；同人同帖 10s 防刷闸门复用。
- **点赞**：uk(post_id, user_id) 唯一约束天然幂等；点赞/取消走
  INSERT-ON-CONFLICT-DENY + DELETE，计数同步增减；Redis 记用户点赞过期集合
  加速"是否已赞"回显，DB 为事实源。
- **审核复用**：独立开关 `forum_audit` + 敏感词库共用；管理员审核队列增加
  来源类型筛选（物品/帖子/回复三队列合一）。举报 P1（复用审核处置）。

### 3.3.2 公告设计
- **公告 `announcement`**：标题 + 内容 + 状态（草稿→发布→下架）+
  置顶标记 + 生效时间窗（可选过期自动下架）；管理员三入口（CRUD + PATCH top）。
- 呈现：首页顶部横幅取"最新一条已发布"，公告列表页分页；
  公开 GET 免登录（白名单路径），内容仅管理员可编辑。
- 公告图片复用 file 模块（同套魔数校验），公告删除连带清图。

### 3.4 认证与权限
- 学号+密码注册（学校场景假设无统一身份对接；预留 CAS/OAuth 接口位）；
- JWT 无状态 + Redis 黑名单（登出/改密下线）；
- RBAC：STUDENT / MANAGER（学生会失物中心）/ ADMIN 三角色；
  敏感词过滤 + 先审后发开关（系统参数可配置，与博客系统 M5 同款机制）。

### 3.5 安全设计
- 图片：扩展名+MIME+魔数三重校验，uuid 重命名，禁止执行目录；
- XSS：描述纯文本存储，前端转义渲染；
- 越权：可见性矩阵（联系方式仅登录后可见，核验答案仅发布者可见）；
- 防刷：发布频率限制（同人 1 分钟 1 帖），认领申请幂等。

## 4. 开发与质量方案

| 实践 | 做法 |
|---|---|
| 分支模型 | main（可发布）+ feat/Mx 分支，完成一模块合一次并打 tag |
| CI | GitHub Actions：push 触发后端 `mvn verify`（H2 库）+ 前端 vitest，覆盖率 ≥60% 门禁 |
| 测试策略 | 状态机矩阵用例（认领 7 路径×角色）为测试核心；接口测试 MockMvc 全链路 |
| 文档先行 | 每模块先写 API 契约再编码，文档与代码同仓库同步提交 |
| 提交规范 | feat/fix/docs/test/chore(scope): 描述；每模块 feat 与 docs 分两次提交 |
| 种子数据 | 幂等 INSERT IGNORE，保证 compose up 后开箱有演示数据 |

## 5. 数据库设计（概要）

| 表 | 用途 |
|---|---|
| sys_user / sys_role / sys_user_role / sys_permission / sys_role_permission | RBAC 五件套 |
| lost_item | 物品主表（LOST/FOUND 统一） |
| item_image | 物品图片 |
| item_claim | 认领单 |
| claim_log | 认领流转留痕 |
| forum_post / forum_reply / forum_like | 论坛三件套（帖子/两级回复/点赞，uk(post_id,user_id) 幂等） |
| announcement / announcement_image | 公告主表（状态机+置顶+时间窗）/ 公告配图 |
| category / campus_area | 分类字典 / 校区楼栋位置 |
| notification | 站内消息 |
| sensitive_word | 敏感词 |
| favorites | 收藏 |
| sys_config / operation_log | 系统参数 / 管理操作审计 |

（全 22 表，DDL 见 backend/src/main/resources/db/mysql/schema.sql。统一纪律：全部表自增 id 主键——关联表用联合主键会让 MyBatis-Plus 的单主键 API（selectById/deleteById）失效，改用 id+唯一键组合表达同等约束，幂等语义不变）

## 6. 接口设计（摘要）

- `POST /api/items` 发布；`GET /api/items` 检索（type/分类/关键词/校区/时间，分页排序）
- `GET /api/items/{id}` 详情（浏览计数）；`PATCH /api/items/{id}/status` 状态流转（下架/重上架）
- `POST /api/items/{id}/claims` 申请认领；`PATCH /api/claims/{id}/verify` 核验通过/拒绝
- `POST /api/claims/{id}/confirm` 确认归还；`POST /api/claims/{id}/arbitrate` 申请仲裁
- `GET /api/items/{id}/matches` 相似推荐；`GET /api/notifications` 消息
- 论坛：`GET /api/forum/posts` 板块列表（分页排序）；`POST /api/forum/posts` 发帖（含图）；
  `GET /api/forum/posts/{id}` 详情（浏览计数）；`POST /api/forum/posts/{id}/replies` 回复（两级封顶）；
  `POST /api/forum/posts/{id}/like` 点赞（幂等，再调取消）；`PATCH /api/admin/forum/{type}/{id}/audit` 帖子/回复审核
- 公告：`GET /api/announcements` 公开列表（免登录）；`GET /api/announcements/active` 首页横幅用；
  `POST /api/admin/announcements` 新建；`PATCH /api/admin/announcements/{id}/status` 发布/下架；
  `PATCH /api/admin/announcements/{id}/top` 置顶
- `GET /api/admin/items/pending` 审核队列（物品/帖子/回复三类型合一）；`PATCH /api/admin/items/{id}/audit` 审核
- `GET /api/admin/stats/dashboard` 统计（找回率/分类分布/周趋势/论坛热度）
- 统一响应体 `{code, message, data, timestamp}`，业务码分段（1xxx 用户/2xxx 物品/3xxx 认领/4xxx 文件/5xxx 论坛/6xxx 公告）
